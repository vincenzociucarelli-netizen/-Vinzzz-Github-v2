Additionally, the user requested a comprehensive end of trial period flow with two distinct paths: one for athletes who want to stay (requiring them to complete a 3-step process) and one for athletes who want to leave (initiating a data deletion request that an admin must approve after checking for administrative obligations). **PRODUCT REQUIREMENTS**:
*   **Pre-Season Registration Feature**:
    *   An admin-configurable campaign with a title, season, and open/close dates.
    *   A public, shareable link to a form where new or existing athletes can register their interest.
    *   The form should collect: Name, DOB, contact info (athlete/parent), previous team/championships played, and role.
    - An admin dashboard to create/manage campaigns, view all responses, and export them to a / file.
*   **End of Trial Period Feature**:
    *   From the parent/athlete view, a single Conferma / Rinuncia (Confirm / Waive) button to start the process.
    - If Confirm is chosen, the athlete must complete a 3-step process to become an active member: 1. Enter medical certificate expiry date, 2. Get admin verification of the certificate, 3. Sign the privacy/GDPR agreement.
    - If Waive is chosen, a data deletion request is sent to the admin.
*   **Data Deletion Flow**:
    *   The deletion must be approved by an admin.
    - Before deletion, the system must check for outstanding administrative/fiscal obligations (e.g., unpaid fees, tax documents issued). Deletion is blocked if obligations exist.
    - The flow should delete all related data: athlete record, signed documents, attendance, certificates, etc.
    - The parent's account should ONLY be deleted if they have no other children in the system and no outstanding obligations.
*   **Notification System**:
    - Admins should be able to send email notifications to parents of currently registered athletes to invite them to the pre-season campaign.
    - The system should be smart enough not to send reminders to parents who have already responded.
